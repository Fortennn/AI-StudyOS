# Підготовка та розгортання (`AI StudyOS`, ПР20)

## 1. Складові застосунку під час роботи

| Складова | Тип | Пам'ять / Диск | Поведінка після перезапуску / нового деплою |
| :--- | :--- | :--- | :--- |
| **FastAPI + Uvicorn (`app.main:app`)** | Вебсервер (1 worker) | ~90–140 МБ RAM | Перезапускається платформою; працездатність перевіряється через `GET /api/health` |
| **SQLite (`DATA_DIR/study.db`)** | Стан (історія, користувачі) | < 10 МБ на диску | На тимчасовій ФС (Free Tier) скидається при редеплої → ініціалізується `python -m app.init_data`; для збереження монтується Persistent Disk у `DATA_DIR` або підключається зовнішня БД |
| **TTL-кеш (`app/cache.py`) та `Idempotency-Key`** | Стан у RAM | ~10–30 МБ RAM | Свідомо втрачається при перезапуску (не критично, відновлюється наступними запитами) |
| **`UserRateLimiter` та `CircuitBreaker`** | Стан у RAM | < 1 МБ RAM | Скидається при старті процесу |
| **Лічильник бюджету (`DATA_DIR/budget.json`)** | Стан на диску | < 1 МБ | На тимчасовій ФС може обнулитися при перезапуску, тому остаточним запобіжником витрат є квота в кабінеті провайдера (`Google AI Studio`) та `DEMO_TOKEN` |
| **Журнал (`logs/app.log`, `logs/app.jsonl`)** | Ротовані файли + `stdout` | до 8 МБ (ротація) | Платформа збирає `stdout`; локально зберігаються ротовані файли у `logs/` |
| **Gemini API (`generativelanguage.googleapis.com`)** | Зовнішній сервіс | 0 локально | Викликається через `httpx` з таймаутом `LLM_TIMEOUT_S` |
| **Локальні ML-моделі / важкі системні пакети** | Відсутні | 0 | Не використовуються — усі обчислення LLM винесені у хмарний API |

## 2. Вибір середовища розгортання

- **Обране середовище:** **Render Web Service (Free Tier)** або будь-який контейнерний хостинг (Railway / Fly.io / VPS з Docker) через `Procfile` або `Dockerfile`.
- **Обмеження безкоштовного рівня Render (станом на 26.11.2026):**
  - RAM: `512 MB` (достатньо, оскільки застосунок споживає ~120 МБ без локальних ваг моделей).
  - Засинання: інстанс засинає після ~15 хв простою (перший запит після пробудження може тривати 20–40 с; UI обробляє це індикатором очікування і кнопкою скасування).
  - Ефемерний диск: файлова система очищається при новому деплої/перезапуску (у проєкті немає критичних втрат на демо-даних, а БД ініціалізується через `python -m app.init_data`).
  - Ліміт часу HTTP-відповіді проксі: 100 с (спільний дедлайн `LLM_TOTAL_DEADLINE_S=45` вкладається із запасом).
- **Альтернативи:**
  - Власний VPS (знімає засинання та дає постійний диск, але вимагає ручного адміністрування HTTPS/проксі/оновлень ОС — надлишково для навчального проєкту, хоча `Dockerfile` повністю готовий і для VPS).

## 3. Кількість процесів та ініціалізація

- **1 робочий процес (`uvicorn app.main:app --host 0.0.0.0 --port $PORT`):** `UserRateLimiter`, `CircuitBreaker`, `StudyResponseCache` та `_IDEMPOTENCY_CACHE` зберігаються в пам'яті процесу. При запуску кількох воркерів (`--workers 2`) кожен мав би окремий лічильник і ліміт став би удвічі м'якшим; для масштабування понад 1 процес цей стан потрібно виносити в Redis.
- **Ініціалізація даних:** `python -m app.init_data` — ідемпотентний скрипт, який створює таблиці та базовий демо-запис, якщо БД порожня.

## 4. Захист публічної адреси та відкат

- **Захист від чужих витрат:**
  1. `DEMO_TOKEN` (опційно в продакшні) закриває `/api/generate`, `/api/chat`, `/api/upload` (порівняння через `secrets.compare_digest`), залишаючи відкритими `/api/health` і статику.
  2. `USER_RATE_LIMIT_RPM` (наприклад, `10` запитів/хв на клієнта).
  3. `BUDGET_DAILY_USD` / `BUDGET_DAILY_CALLS` + жорсткий ліміт у кабінеті Google AI Studio.
  4. `AI_ENABLED=0` — миттєве вимкнення AI-генерації без зупинки сервера.
- **Версіонування та відкат:**
  - `GET /api/health` повертає `extra.git_commit` (із `RENDER_GIT_COMMIT` / `GIT_COMMIT`), `extra.prompt_version` (`v1`) і `model`.
  - Стабільна версія позначається тегом (`git tag -a v1.0 -m "версія для захисту"`). Відкат: у панелі платформи обрати попередній деплой або відкотити гілку до тегу `v1.0`.
